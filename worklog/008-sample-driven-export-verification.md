## 1. Context

A sample application (the classic **MusicCart** demo, project `MUSICSHOP`) was
loaded in the live IDE. That made it possible to settle the items previously left
tagged `[verify]` in [docs/uniface-10-onboarding.md](../docs/uniface-10-onboarding.md)

## 2. On-disk artifact map (verified)

Inspecting the project dir
(`C:\Users\Bob\Rocket Uniface 10 Community Edition\project`) and the install's
`webapps`:

| Artifact | On-disk location | Nature |
| --- | --- | --- |
| Compiled runtime object | `project\resources\<type>\<name>.<type>` (`dsp` `usp` `frm` `svc` `aps` `edc` `sig`) | Binary-headered; **embeds** the XHTML/template. Not hand-editable. |
| Generated DSP client JS | `…\webapps\uniface\dspjs\<name>.js` | Header: *"This source is generated by UNIFACE"* — **output**, not input. |
| Compiler / debug meta | `project\<name>.cmi` | JSON mapping runtime ↔ source positions (debugger). |
| **XML export (VCS bridge)** | `project\<class>_<name>.xml` (e.g. `cpt_musiccart.xml`) | Repository serialization `<DSC>/<FLD>/<DAT>`, `release="10.4" repversion="8"`. |
| Framework static web assets | `…\webapps\uniface\{css, common, templates, webserver, WEB-INF}` | Shared, file-based. |

**Key correction to the earlier draft:** a DSP/USP's **page markup (XHTML) is
stored in the repository** (as `UXGROUP`/`UXFIELD` entities) and is *embedded into
the compiled object* at compile time. It is **not** a standalone editable `.html`
on disk. So the per-component layout is an IDE artifact (Component Editor → Design
Layout), and only **shared** web assets, config, and scripts are genuinely
file-authorable in VSCode. Onboarding §1.5 was rewritten accordingly.

## 3. Export facility (verified)

- **Click-path:** select the object → **Export**. At project level,
  `prj: MUSICSHOP` → **Export** writes the whole project.
- **Granularity is selectable**, proven by comparing two real exports:
  - **Single component** — `cpt_musiccart.xml` (45 KB) = **3** repository tables:
    `UFORM` + `UXGROUP` + `UXFIELD` (definition + UX page layout).
  - **Full project** — `export-all-sample` (1.8 MB, 47 089 lines) = **all 31**
    object classes: `UAPPL`, `UPROJECT`, `UFORM`, the `UC*` component tables
    (`UCTABLE`/`UCFIELD`/`UCKEY`/`UCGROUP`/`UCRELSH`), `UX*` layout, the `US*`
    service spec/signature/operation tables (`USSPEC`/`USPARM`/`USOPER`/`USIMPL`…),
    the `U*LIB*`/`UINC`/`UPRC`/`USNP` libraries, and `UREF*` cross-references.
  - Both share the header `<UNIFACE release="10.4" repversion="8" xmlengine="2.0">`.

## 4. Empirical disproof — there is no `/exp` switch

Hypothesis under test: "`ide.exe /exp /all` exports everything." Running it against
the live install produced **exit code 1** and the IDE log
(`log\ide_16040.log`) recorded:

```
Command : "…\ide.exe" "/adm=…\uniface\adm" /exp /all, pid=16040
0099 - Command line string not acceptable; please check syntax and spelling.
```

This matches the switch reference, which has **no** `/exp` (only `/ex` =
"exclusive Uniface Server", unrelated). **Conclusion:** there is no command-line
export. Use the IDE **Export** action or ProcScript `$ude("export")`; the command
line offers only **`/imp`** (import). Worth keeping as a teachable note alongside
worklog/005's "switch names aren't self-evident."

## 5. ProcScript status variables (verified from the sample's own code)

Rather than guess the 10.4 set, the variables were mined from the MusicCart
ProcScript inside `export-all-sample`. Confirmed in use:
- **`$status`** — call/operation status.
- **`$procerror`** — ProcScript error code (**negative = error**).
- **`$procerrorcontext`** — string context for the error.

Idiom, verbatim from the sample:

```
if ($status = 0)
  if ($procerror < 0)
    procerror = $procerror              ; capture into an OUT param
    procerrorcontext = $procerrorcontext
    return (0)
```

Services propagate the error outward via signature params
(`numeric procerror : OUT`, `string procerrorcontext : OUT`).
